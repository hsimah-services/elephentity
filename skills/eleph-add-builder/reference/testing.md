# Verifying a builder

## Order

1. Build the binary; send it a `describe` request with no schema or config. It must
   answer.
2. Send malformed input and a mismatched envelope. Expect non-zero exit, a diagnostic on
   stderr, **no** stdout response.
3. Send a semantic error (bad config, name collision). Expect `errors` populated and an
   empty `files`.
4. Send a real request. Inspect the files by eye **before** freezing them.
5. Compile or load the output against the real runtime (see the runtime-specific skill).
   Snapshot equality proves stability, not that the output works.
6. Generate a small real project through the real `eleph` and `eleph-codegen`.
7. Run `eleph generate --check`, then `eleph check`. They catch different drift.
8. Push and read CI before saying it is done.

Containers, not host tools: `./tools/cargo cargo …`, `./tools/php …`,
`./tools/dotnet dotnet …` from the repository root.

## Protocol lessons

- Return PHP bodies without the opening tag; the orchestrator adds the header.
- PHP encodes an empty map as `[]`; typed decoders must accept that.
- A nullable wire member may still be required; keep the decoder's presence checks.
- Independent targets compose: entity, storage and API output are separate targets that
  each sweep only their own directory. Nest storage/API output under the entity output
  directory if the checker looks there (the PHP check finds one-level child `verify.php`).
- Repository name, package name, executable, target name and integration key may all differ.
  Write them down in the README.
- Two names that collide after your language's casing rules are an error, not a rename.
- Escape SQL values and language literals separately. Never interpolate schema text as code.

## Refreezing

Golden outputs are regenerated by an env var in the existing builders
(`ELEPH_REFRESH=1 cargo test --locked every_golden` in the C# builder). Review the diff:
an unexpected change in generated bytes is the signal this machinery exists to give.

## Cross-boundary changes

Three things are copied rather than shared: the IR (`rust/ir.rs`), runtime names (strings),
and the `provides` shape. Changing the IR shape means bumping the version gate in the
compiler, the orchestrator and every builder together; see `.llms/cross-repo.md`.
