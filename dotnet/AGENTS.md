# Elephentity for .NET

The runtime, storage adaptors (SQLite, Cosmos), GraphQL and tsquid support that C# code generated by
Elephentity runs on. Read the [.NET epic](https://github.com/hsimah-services/elephentity/issues/115)
first: it holds the decisions, the design and the ordered steps, and this file assumes it.

## Working in this repository

There is no host dotnet. Everything runs in a container:

```bash
./tools/dotnet dotnet format --verify-no-changes
./tools/dotnet dotnet build -c Release
./tools/dotnet dotnet test
./tools/dotnet dotnet pack -c Release -o artifacts -p:Version=0.0.0-ci
```

`tools/dotnet` runs `mcr.microsoft.com/dotnet/sdk:10.0`, podman first and docker as a
fallback, with NuGet cached under `${XDG_CACHE_HOME:-$HOME/.cache}/eleph/nuget`. Use it for
everything, including `dotnet new` and `dotnet add package`. Fix formatting with
`./tools/dotnet dotnet format`; CI runs it with `--verify-no-changes`.

CI must be green before a step is done. The libraries build with warnings as errors, so a
warning is a failed build.

## Layout

| Path | Holds |
|---|---|
| `src/Elephentity.Runtime` | Port of `elephentity/packages/runtime` (steps 10 and 11) |
| `src/Elephentity.Runtime.Memory` | Port of `packages/memory` (step 12) |
| `src/Elephentity.Runtime.Testing` | Port of `AdaptorConformance` as framework-agnostic cases, plus `ContractCheck` and `StubEntityCatalogue` (step 12) |
| `src/Elephentity.Runtime.Testing.Xunit` | The xUnit base class that runs the conformance cases as a theory (step 12) |
| `src/Elephentity.Cosmos` | The Cosmos DB adaptor, installer and backup (step 15); see [docs/cosmos.md](docs/cosmos.md) |
| `src/Elephentity.Sqlite` | The SQLite adaptor and installer, a port of `packages/sqlite`; see [docs/sqlite.md](docs/sqlite.md) |
| `src/Elephentity.GraphQL` | GraphQL.NET, the same schema as `elephentity-graphql-php` (step 17) |
| `src/Elephentity.Tsquid` | Server-side initial data for tsquid (step 19) |
| `tests/*.Tests` | One xUnit v3 project per package |

Build settings live in `Directory.Build.props` (everything), `src/Directory.Build.props`
(the packages) and `tests/Directory.Build.props` (the tests). Package versions are decided
once, in `Directory.Packages.props`. Do not put a `Version` on a `PackageReference`.

## Conventions that are load bearing

- **Port by name.** Every type ports from its PHP source in
  `elephentity/packages/runtime/src/...`, keeping its name and its tests. When the PHP code
  and its README disagree, the code wins. Say in the PR which file a type was ported from.
  [docs/divergence.md](docs/divergence.md) lists every place the names or the behaviour
  differ and why (the `I` prefix, the `Async` suffix, the `Exception` suffix, and a handful
  of names a .NET analyzer refuses). Add to it in the same PR as the difference.
- **Async-first is the only intended divergence.** The storage port, gateway and queries
  take a `CancellationToken` and return `Task` or `ValueTask`, because the Cosmos SDK is
  asynchronous. Anything else that differs from PHP is a bug in one of the two, or a
  decision to write down.
- **No reflection in hot paths.** Generated code uses none, and the libraries stay
  `IsAotCompatible`. A trimming or AOT warning is a defect, not noise to suppress.
- **Errors accumulate.** Verifiers and planners collect every problem and report them
  together, as they do in PHP.
- **Never edit generated files.** Change the builder and regenerate.
- **MIT everywhere.** Every package declares `PackageLicenseExpression` MIT.
- **Every public member is documented.** The build generates the XML documentation file with
  warnings as errors, so a missing comment fails it. Reuse the PHP comment where it carries
  the reasoning.
- **Keep it simple.** This is a runtime for generated code, not a framework. No
  abstraction with one implementation, no option nobody asked for.

## Before you commit anything that crosses a program boundary

The C# builders name types and constructors in this repository as strings
(`rust/runtime.rs`), so renaming one is invisible here and fails in a generated project.

**[`.llms/cross-repo.md`](../.llms/cross-repo.md) is the closed list of what crosses.** If you
changed something on it, open an issue on each repository it reaches, before or with the
push. [`.llms/README.md`](../.llms/README.md) has the rule and
[`.llms/issue-template.md`](../.llms/issue-template.md) the shape. There is one copy of the `.llms/` files, at the root of the monorepo; do not copy it here.
